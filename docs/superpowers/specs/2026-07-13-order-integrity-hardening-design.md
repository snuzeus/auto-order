# 주문 무결성 보강 설계

## 목표

상품마스터 교체, 주문 제출, 납품처 메일 발송, 보관 기간 정리 과정에서 주문 데이터가 바뀌거나 누락되지 않도록 한다.

## 범위

1. 주문 항목에 당시 단가와 최소발주수량을 저장한다.
2. 주문 API와 DB 함수에서 활성 등록 상품만 허용한다.
3. 상품마스터 엑셀에서 상품코드, 상품명, 납품 거래처명, 공급가를 필수값으로 검증한다.
4. Resend 호출은 성공 여부와 관계없이 각 호출 사이에 간격을 둔다.
5. 어제 이전 주문을 정리할 때 같은 날짜의 메일 발송 이력도 삭제한다.

## 데이터 설계

`order_items`에 `unit_price numeric(12, 2) not null default 0`와 `minimum_order_quantity integer`를 추가한다. 주문을 제출하는 DB 함수는 `products`에서 현재 상품 정보를 직접 조회하고, 그 조회 결과를 주문 항목에 저장한다. 클라이언트가 전송한 상품명, 단가, 납품처는 신뢰하지 않는다.

상품마스터 교체는 원자적으로 수행하되, 같은 바코드의 상품은 갱신하고 파일에 없는 기존 상품은 비활성화한다. 따라서 이미 저장된 주문의 상품 ID 연결은 유지된다. 주문 화면과 합계는 주문 항목의 스냅샷 단가를 우선 사용한다.

## 주문 검증

제출할 각 항목은 활성 `products` 레코드의 ID, 바코드, 상품코드와 일치해야 한다. 하나라도 일치하지 않거나 상품 ID가 없으면 DB 함수는 `REGISTERED_PRODUCT_REQUIRED` 오류를 낸다. 최소발주수량 검증도 DB 함수에서 조회한 값으로 처리한다.

## 엑셀 검증

상품마스터 파일은 `상품코드`, `상품명`, 납품 거래처명 별칭, 공급가 별칭을 가져야 한다. 각 비어 있지 않은 행은 네 값이 모두 필요하다. 단가 0은 허용하되 빈 값은 허용하지 않는다.

## 메일 및 보관

발송 시도 횟수를 기준으로 600ms 간격을 적용한다. 실패한 메일도 한 번의 발송 시도로 계산한다. 주문 정리 함수는 `supplier_email_logs`에서 어제 이전 이력을 먼저 삭제한 뒤, 기존 마감·주문 정리를 수행한다.

## 테스트

주문 스냅샷, 등록 상품 검증, 엑셀 필수값, 실패 뒤 발송 간격, 메일 이력 정리를 각각 단위 테스트로 고정한다. 기존 주문 API와 업로드 API 테스트도 새 계약에 맞게 갱신한다.
